# UX and UI standard

- **UX-001** [review] [blocking] Every screen or component that loads data handles all its states: loading, empty, error and success.
- **UX-002** [review] [blocking] Everything can be reached and used with the keyboard alone, in a sensible order, with a visible focus indicator.
- **UX-003** [review] [blocking] Every input has a label, every meaningful image has alt text, and custom controls have the right role and name.
- **UX-004** [review] [blocking] Text and controls meet WCAG AA colour contrast, and nothing is conveyed by colour alone.
- **UX-005** [review] [blocking] Error messages say what went wrong and what to do next, in plain words, beside the thing they refer to.
- **UX-006** [review] [advisory] The change uses the existing components, spacing, type and colours. No one-off styles where a shared one exists.
- **UX-007** [review] [blocking] The layout works at phone width (360px) with no sideways scrolling and touch targets of at least 44px.
- **UX-008** [review] [blocking] Destructive actions ask for confirmation or can be undone.
- **UX-009** [review] [blocking] What the user typed is kept when a submit fails.
- **UX-010** [review] [advisory] An action gives feedback within a moment: a pressed button shows it is working and cannot be submitted twice.
- **UX-011** [review] [advisory] Words are consistent with the rest of the product: the same thing has the same name everywhere.
- **UX-012** [review] [advisory] Long, missing or odd values (a 60-character name, no avatar, zero results) do not break the layout.
